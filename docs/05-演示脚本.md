# 05 · 演示视频脚本（5–8 分钟）

> SecAgent · 智能体驱动的 AI 安全知识情报系统

---

## 使用说明

**本文件是什么**：初赛/决赛「操作演示视频」的逐镜头拍摄脚本。全片按"某企业安全运营中心的一个早晨"叙事线推进，目标时长 **6 分 50 秒**（可压缩至 5 分、拉伸至 8 分，各场景标注了弹性空间）。

**怎么用**：
1. 录制前先通读一遍，按 §1「演前检查单」把环境和浏览器页签备好；台词不必逐字背，但每段的**关键数字和结论句**必须说出来（脚本中加粗处）。
2. 正式录屏建议完整走 2–3 遍取最好一条；问答场景可单独补录后剪辑拼接。
3. §5「风险与兜底」务必提前演练——演示当天没有新漏洞、网络断连、测绘无权限，都有备案。

**时长分配总览**：

| 段落 | 内容 | 时长 |
|---|---|---|
| S0 | 开场·痛点 | 0:30 |
| S1 | 亮出架构 | 0:45 |
| S2.1 | 新 CVE 入库·实时推送 | 0:50 |
| S2.2 | 情报卡富化全景 | 1:10 |
| S2.3 | 多跳深度问答（3 题） | 1:50 |
| S2.4 | 知识图谱探索 | 0:30 |
| S2.5 | 日报自动生成 | 0:30 |
| S3 | 指标背书 | 0:30 |
| S4 | 收尾 | 0:15 |
| | **合计** | **≈6:50** |

**三条铁律**：
- **数字必须真实**：所有说出口的指标以 §4 实测表为准，不夸大；模拟数据主动声明（见 S2.2）。
- **多跳问答会流式输出约 40–50 秒**：这是深度推理模式（多轮检索+纠偏+KG 桥接）的正常表现，等待期间按脚本解说推理链，**不要沉默、不要快进**。
- **演示视频不强制匿名**（决赛答辩 PPT 才要求匿名），但建议同样不出现校名队名，一版素材两处复用。

## 1. 演前检查单（录制前 10 分钟逐项确认）

```bash
# ① 基础设施 + 全栈（在 deploy/ 下）
cd deploy && docker compose up -d
# 或本地开发模式：
docker compose up -d postgres qdrant neo4j redis
cd backend && .venv/bin/uvicorn app.main:app --port 8000

# ② 演示数据（已跑过可跳过；重放前先清库可选）
cd backend && .venv/bin/python ../scripts/demo_seed.py

# ③ 健康检查
curl -s http://localhost:8000/api/health    # 期望 ok
# 前端打开 http://localhost:3200（生产）或 :3000（dev）
```

**浏览器预开 6 个页签**（从左到右，录屏时只按顺序切换，不现场输地址）：

| # | 页签 | 用途 |
|---|---|---|
| 1 | 架构图（技术报告中的总体架构图 / PPT 架构页） | S1 用 |
| 2 | 态势总览 `/` | S0/S2.1 用 |
| 3 | 数据源 `/sources` | S2.1 用 |
| 4 | 深度问答 `/qa` | S2.3 用 |
| 5 | 知识图谱 `/graph` | S2.4 用 |
| 6 | 报告 `/reports` | S2.5 用 |

**其他准备**：
- 浏览器缩放调到 **110–125%**，隐藏书签栏；录屏 1080p。
- 提前在"情报库"搜索 `CVE-2024-37032` 确认该条目存在且富化字段齐全（PoC/资产/论文/攻击链），把结果页留作备用页签。
- 确认外网可通（S2.1 现场采集用）：`curl -sI https://hn.algolia.com` 通即可；不通则启用 §5 兜底方案 B。
- 终端窗口备好但不入镜（应急用）。

## 2. 角色与叙事设定

- **场景**：某企业安全运营中心（SOC），早上 8:45。
- **主角**：值班分析师"小周"（只闻其声=旁白，不出镜）。
- **故事弧**：小周上班 → 发现系统凌晨已自动抓到一批新情报 → 点开一条高危漏洞看系统"查好了多少" → 用自然语言追问三个递进问题 → 在图谱上验证推理路径 → 九点例会前自动生成日报。
- **情绪基调**：克制、专业，"系统替人值了一夜班"的省心感。全程不说"很厉害/很强大"，让画面和数字说话。

**画面**：黑场起，淡入"态势总览"大屏（页签2）：6 个指标卡、14 天趋势曲线、L1–L6 分布环图、高优先级情报流。镜头缓慢平移一次。

**台词**（旁白，语速放慢）：

> "早上八点四十五，某企业的安全运营中心。值班分析师小周刚坐下——过去一年，AI 相关漏洞信息散落在 CVE 库、厂商公告、几十个中英文社区、论文和邮件列表里，光是把它们看完，一个班都不够。
>
> 而屏幕上的这套系统，已经替他值了通宵的班。"

**预期画面**：指标卡显示 `情报总量 600+`、`24h 新增`、`AI 相关`、`KEV 在野`、`PoC 可用`、`数据源 xx/41` 健康度。趋势图有连续 14 天数据。

**拍摄提示**：如 `24h 新增` 为 0，先手动触发一次采集（见 S2.1 操作）再补录本镜头；或挑趋势图里最高的那一天讲"凌晨两点，又进来一批"。

**画面**：切到页签1（总体架构图）。光标沿"表现层 → 智能体编排层 → 四大能力层"自上而下走一遍；在编排层三个方框上各停留 1 秒。

**台词**：

>
> 底下是四个能力层：**十一类数据源**的监测层、**十多个维度**的富化层、向量库加知识图谱的知识层，和容器化加监控告警的工程层。"

**预期画面**：架构图清晰可读（字体不小于 12pt 等效）。若用 PPT 页代替，确保图中"Pipeline DAG / QueryAgent / AnalystAgent"三块可辨认。

**弹性**：时间紧可砍掉编排层展开，压到 25 秒（只保留"三层混合编排 + 四大能力层"两句）。

### S2.1 · 场景一：新 CVE 入库·实时推送（1:15–2:05）

**叙事点**：还原"凌晨系统自动干活"的一刻，现场触发一次采集。

**操作步骤**：
1. 切到页签3「数据源」：表格列出全部已注册源及健康状态。
2. 在 `hackernews`（或 `cisa_kev`）行尾点「**采集**」按钮；按钮变 `…`，几秒后恢复。
3. 切回页签2「态势总览」，按 `F5` 刷新。
4. 光标依次停在 `24h 新增` 指标卡和高优先级列表顶部的新条目上。

**台词**：

> "系统注册了**四十一个具体源，覆盖十一大类**：CVE 官方库走 git 增量，每十五分钟就拉一次 diff；NVD、GHSA、KEV、厂商 CSAF、二十多个中英文 RSS、邮件列表、政策源，各自有独立游标。
>
> 我手动触发一次，模拟凌晨那次调度。（点击采集，等 2–3 秒）采集不是简单堆进来——每一条都要过**四层去重**：URL 哈希、CVE/GHSA 编号对齐、SimHash、MinHash-LSH，合并掉不同源报道的同一件事。
>
> （刷新大屏）看，新增已经进来了。"

**预期画面**：数据源表格显示源名、类型、状态、最近采集时间；大屏刷新后 `24h 新增` 数字上升或列表出现新卡片。

### S2.2 · 场景二：情报卡富化全景（2:05–3:15）

**叙事点**：一条原始 CVE 进来只有几十个字，系统把它"查成了一页情报档案"。

**操作步骤**（主角条目用 **CVE-2024-37032 Ollama Probllama**，实测富化最全）：
1. 在大屏高优先级列表找到该卡片；若不在前 8，切「情报库」搜索框输 `CVE-2024-37032`，点卡片进详情页。
2. 进详情页后**从上到下慢速滚动**，每到一个区块停 2–3 秒配台词：
   - 顶部徽章行（critical / CISA KEV / PoC 可用 / L1 层 / ASI05）
   - 左侧评分格（CVSS 9.1、**EPSS 0.897、百分位 99.8%**、利用成熟度 weaponized、优先级 0.97）
   - 中文摘要段
   - 「攻击链推演」三段流程条
   - 「PoC / EXP（9）」列表，停在 `suspicious` 徽章上
   - 「受影响互联网资产」≈**5312** 暴露（有"模拟数据"标记）
   - 「关联论文/分析（5）」
   - CWE-22/CWE-345 → ATLAS、受影响版本、缓解建议
   - 底部「相关情报」+ 右上角「重新富化」按钮

**台词**（滚动时连续说，不要求逐块对齐）：

> "挑一条凌晨入库的高危——Ollama 的 Probllama 漏洞。原始公告只有一段英文描述，现在这页卡片上：**CVSS 9.1，EPSS 0.897，意思是被利用概率排进全部 CVE 的前 0.2%**；CISA KEV 标记说明它已经在野被用了。
>
> 系统找到了**九个公开 PoC**，并且做了可信度分级——注意这个 suspicious，GitHub 上的 PoC 仓库有相当比例是带毒的，直接照单全收本身就是风险。
>
> 往下的资产测绘告诉我们全球大约五千多个暴露实例——这里要说明：测绘接口的付费权限我们没有，页面标了'模拟数据'，但管线是通的，接上正式 key 就是真实数据。
>
> 再往下，五篇关联论文、CWE 到 ATT&CK 的技术映射、受影响版本区间、中文缓解建议，还有一段**自动生成的攻击链**：初始访问、执行、影响。这全部是同一条流水线里**八个富化 worker 并发跑出来的**，每个维度都带置信度，低置信的宁可标'存疑'进复核队列，也不写错。"

**预期画面**：详情页一屏放不下，滚动过程本身就是"维度多"的证明。徽章、评分、PoC 可信度彩色标识清晰可见。

### S2.3 · 场景三：多跳深度问答（3:15–5:05）

**叙事点**：分析师真正的早晨工作——追问系统。三题难度递进，全部来自系统自建评测集（`scripts/eval_qa.py`），答案可复现。

**操作**：切到页签4「深度问答」。逐题在输入框键入并回车。**等待期间按台词解说，不剪辑跳跃**。

**第 1 题（单跳·事实直取，实测 ≈2 秒）**：

键入：`CVE-2025-32444 影响哪个组件？严重度是多少？`

> "先问个简单的。（回车）——两秒，vLLM，严重级，**9.8 分**。底下有引用编号，点引用能跳回原始情报，不是模型背出来的。"

**预期**：答案含 vLLM / critical / 9.8；气泡下方显示 `置信度 xx% · 链路: …`，引用列表可点。

**第 2 题（三跳·KEV 枚举+归因，实测 ≈47 秒流式）**：

键入：`哪些 AI 基础设施漏洞已被 CISA KEV 收录并遭在野利用？它们的攻击链有什么共同点？`

> "加难度。这个问题要先在 KEV 目录里圈出在野利用的，再过滤到 AI 基础设施，最后把几条攻击链摆在一起找共性——人做要开十几个页面。
>
> （等待流式输出时）看底下这条链路：路由判定这是多跳问题，拆成子查询，向量加稀疏双路召回，重排之后发现证据不够，又回知识图谱里沿最短路径补了一跳——这就是它回答'共同点'的底气。
>
> （答案出来后）Ollama、Langflow，还有 ShadowRay 那个争议 CVE，它特意标了'disputed 但在野利用'——**影子漏洞**，正式目录里差点漏掉的威胁。"

**预期**：答案覆盖 CVE-2024-37032 / CVE-2025-3248（及 CVE-2023-48022），共性指向 T1190（利用公开应用）+ 未认证接口。trace 链路可见多个 step。

**第 3 题（两跳·内网资产风险评估，实测 ≈47 秒流式）**：

键入：`我们内网部署了 Ollama 和 Milvus 2.4，请分析面临的已公开漏洞风险及处置建议。`

> "最后一个，是小周每天真正要回答的问题：'这关我们什么事？'——这个问题库里没有现成答案，Ollama 和 Milvus 是两条独立情报，要**跨文档关联**到自家资产。
>
> （等待时）注意它把'Ollama'和'Milvus 2.4'分别做了实体链接，各查各的受影响版本，再合并成一份处置清单。
>
> （答案出来后）Ollama 对应 Probllama，Milvus 2.4 命中 sourceID 认证绕过，修复版本、临时缓解都给了。原来翻一上午的活，现在一分钟。"

**预期**：答案同时命中 CVE-2024-37032 与 CVE-2025-64513，含"升级版本号 + 加认证/网关删 header"类建议；置信度与引用完整。

**弹性**：如需压到 5 分钟版，第 2、3 题只保留一题（优先留第 3 题，故事性最强），省约 50 秒。

**预期**：力导图展开，中心 CVE 节点向外辐射多色节点（CWE/技术/产品/关联情报），边有类型标签；节点可拖拽。
