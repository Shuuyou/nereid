## 使用说明

**本文件是什么**：初赛要求提交的《技术报告》（Word + PDF 各一份）的章节骨架与写作任务书。每一章给出：要点清单、关键图表、字数建议、以及"**评委看点**"——即该章对应评分表中的哪一行、拿什么分。

**赛题硬性要求**（漏项直接丢文档分）：
- 封面或目录后第 1–2 页为"**重要内容预览页**"，放核心亮点。
- 内容必须涵盖：总体架构设计、智能体方案设计、监测/富化/问答各模块详细设计、关键技术选型说明、系统工作流程图、系统实现细节、**核心代码说明**、各功能模块**实现效果展示**、**性能测试结果与分析**、创新点总结。
- 文档分 15 分："含详细设计图与流程图且逻辑严谨"才进优秀档（12–15）。

**规模建议**：正文 **30–40 页 / 约 2.0–2.4 万字**，图表 25–30 幅。写作时严守一条：**每个性能断言都有实测出处**（`docs/04-实现进展与验证.md`、`reports/eval_qa.json`、`scripts/eval_qa.py`）。

**评分点→章节映射速查**：

| 评分项（初赛） | 分值 | 主战场章节 |

| 监测完整性 | 15 | 第 4 章 |

## 第 3 章 智能体方案设计（≈2500 字 / 4 页）—【Agent 15 分主战场】

**要点**：
- 设计哲学：不是"用了 Agent 框架"，而是**按任务性质选编排模式**——
  - 周期链路 = 确定性 DAG：采集→去重→富化→入库，节点幂等、可重放、部分失败可续跑；
  - 交互链路 = Supervisor-as-Tools：QueryAgent 把混合检索/KG 查询/测绘/报告封装为工具，自主决策调用顺序；
  - 分析链路 = Planner-Executor-Critic：日报/攻击链/专题报告带自我校验回环。
- 状态与记忆：TaskRun 持久化运行记录 + Redis 实时节点态共享中间态；HITL 走 review_status 复核队列（REST 确认/回炉）。
- 工具生态：工具清单表（hybrid_search / kg_path / kg_neighbors / asset_lookup / report_gen…），每个工具注明输入输出契约。
- 防坑设计（体现真实工程深度）：handoff 弹跳预算、supervisor 上下文只回结论、节点幂等。

## 第 4 章 情报监测模块详细设计（≈2500 字 / 4 页）—【监测 15 + 时效 5】

**要点**：
- 11 类源 / 41 个已注册源清单（分类列表：cve 库、NVD、GHSA、OSV、KEV、ExploitDB、厂商 CSAF、AI 专用库、RSS×20+、邮件列表/社交、中文政策源）。
- 分层时效设计表：准实时（cvelistV5 git diff 15min）/ 快速（GHSA/OSV/KEV/HN 15–30min）/ 标准（NVD/RSS 30–120min）/ 每日（arXiv/EDB/EPSS/政策）。
- 采集器契约：`collect(source)->(items, new_state)`，统一 ingest；增量游标、ETag 条件 GET、失败重试与降级（cisa.gov 不可达→GitHub KEV 镜像；GitHub 403→等 token 降级不阻塞）。
- 四层去重流水线逐层讲：URL 规范化哈希 → 编号集合对齐（CVE/GHSA/CNVD/CNNVD/EDB 正则，多编号任一并集命中即对齐）→ SimHash(64, Hamming≤3) → MinHash-LSH(J≥0.7) 近重复合并；附"KEV 目录 URL 误合并"真实缺陷修复案例。
- 自动化：APScheduler 周期编排、断点续采、源健康监控页。

## 第 5 章 情报富化模块详细设计（≈3000 字 / 5 页）—【富化 15 + 准确率 5】

**要点**：
- 10+ 维度总览：评分（CVSS/EPSS/KEV/SSVC）、PoC 发现+可信度分级、资产测绘、论文关联、CWE→CAPEC→ATT&CK/ATLAS 映射、版本区间解析、修复建议、中文摘要、相似情报、攻击链生成、AI 分类标注。
- 8 worker 并发编排：确定性源优先 → 聚合索引 → 配额化搜索/测绘 → LLM 结构化抽取（全部 evidence+schema 校验）→ 确定性校验器闸门 → 低置信 abstain 进复核队列。
- **准确率机制（5 分关键）**：官方字段锁死原则；来源权重（官方 1.0 > 厂商 0.95 > 聚合 0.75 > LLM+证据 0.8 > LLM 推理 0.6）；置信度合并；"宁可缺不可错"abstain。
- 特色子模块各一小节：PoC 三级来源 + 恶意 PoC 静态特征检测（trusted/community/suspicious/malicious）；测绘 query 生成（nuclei 元数据 > 产品映射表 > LLM+语法校验）；攻击链 Attack Flow 风格 JSON+中文叙述；S2 限流熔断降级。
- 实测案例：CVE-2024-37032 全 worker 输出表（status/confidence/产出逐项列）。

## 第 6 章 情报问答模块详细设计（≈3000 字 / 5 页）—【问答 15 + 深度 5】

**要点**：
- Agentic RAG 全流程：上下文化 → 路由（单跳/多跳/概览/域外）→ 实体链接 → 子问题分解 → hybrid 召回（dense top-40 + sparse top-40 → RRF k=60）→ 重排 top-60→12 → CRAG 充分性检查（≤2 次纠偏）→ **KG 最短路径桥接（≤3 跳，路径序列化为可解释证据链）** → 带行内引用生成 → 引用校验 + 置信度 → SSE 流式输出（status/token/trace/citation/done）。
- 为什么必须 hybrid：CVE/CWE/T-ID 标识符词面召回靠 BM42，语义召回靠 dense——缺一边就漏证据。
- 多轮对话与个性化：session 上下文、追问建议生成。
- 可解释性：每题输出推理链（trace.steps）、置信度、逐句引用。
- 评测方法：仿 HotpotQA 从 KG 路径自动造桥接题 + 人工标注 8 题基准集（`scripts/eval_qa.py`），命中关键词法 + 延迟分布。

**图表清单**：
- 图 6-1 问答管线全流程图（从输入到流式输出，标出纠偏回环与 KG 桥接）
- 图 6-2 dense+sparse RRF 混合检索示意
- 表 6-1 8 题评测基准集（题目/类型/跳数/期望命中）——放第 9 章亦可，此处给设计
- 截图 6-1 深度问答页（含推理链展开、引用、置信度）

> **评委看点**："跨文档推理与深度分析"优秀档；KG 桥接多跳是区别于普通 RAG 的硬核点；推理链可视化截图直击"深度问答含推理链"。
