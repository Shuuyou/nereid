## 使用说明

**本文件是什么**：决赛答辩 PPT（PDF 提交）的逐页制作任务书。共 **14 页**（含封面、结尾页），每页给出：内容要点 / 视觉建议 / 讲稿要点（口播，非上屏文字）。

**三条硬约束**：
1. **匿名**：赛题明文要求 PPT 不出现"队伍单位、人名等识别信息"。封面只写作品名 + 赛题；页眉页脚不放校徽/队名；截图注意裁掉浏览器书签栏、终端用户名、代码注释中的署名；文件属性（PDF 元数据作者）导出前清空。
2. **模板**：答辩 PPT 模板由主办单位提供——本大纲只管"每页放什么"，配色字体以官方模板为准套入。
3. **评分对齐**：决赛 100 分 = 功能 30 + 性能 20 + Agent 15 + 工程 10 + 文档 10 + 演示 10 + 创新等综合 5。PPT 的每一句话都要能挂到这上面。

**讲稿节奏**：按 8–10 分钟陈述设计，每页 30–45 秒；P9–P10（演示与实测）是评委注意力峰值，可放慢。**口播数字一律以 `reports/eval_qa.json` / `docs/04` 实测为准**。

**全片叙事线**（与演示视频同一故事，前后呼应）：
痛点 → 架构 → 三模块 → 智能体 → 知识底座 → 演示 → 实测 → 工程 → 对比 → 创新 → 收口。

## P2 · 痛点与赛题理解

- **标题**：AI 安全情报的三个断层
- **内容要点**：
  - 散：漏洞信息分布在 CVE/NVD、厂商公告、20+ 社区、论文、邮件列表、政策文件；
  - 浅：AI 安全 ≠ CVE——提示注入/投毒/Agent 事件/政策法规大多没有 CVE 编号，现有平台不覆盖；
  - 断：从业者要从十几处信息源人工拼凑"影响面—利用情况—修复方案"，应急响应以小时甚至天计。
- **视觉**：左"信息碎片"散点图 → 中间裂隙 → 右"分析师决策"图标；底部一行："赛题要的不是又一个漏洞库，而是能回答问题的情报系统。"
- **讲稿**：30 秒。"传统情报平台解决'有没有'，我们解决'懂不懂'——这是整份方案的出发点。"

## P4 · 情报监测：广度 × 时效 × 去重

- **标题**：11 类 41 源 · 四层去重 · 核心链路 ≤1 小时
- **内容要点**：
  - 源矩阵：CVE 官方库(git 增量)/NVD/GHSA/OSV/KEV/ExploitDB/厂商 CSAF/AI 专用库/20+ 中英 RSS/邮件列表与社交/中文政策源；
  - 分层时效表：准实时 15min（cvelistV5 git diff）→ 快速 30min → 标准 2h → 每日批；
  - 四层去重：URL 哈希 → 编号集合对齐(CVE/GHSA 多号并集) → SimHash → MinHash-LSH 近重复合并；
  - 实测一行：NVD 单轮 576 收/543 新/33 合并。
- **视觉**：左侧源分类矩阵表；右上漏斗图（四层去重）；右下横向时效轴。角标："满分线 7 类 ≥6h → 实测 11 类 ≤1h"。
- **讲稿**：40 秒。强调"自动化程度"分：APScheduler 全程无人值守 + 断点续采 + 失败降级不阻塞（cisa.gov 不可达自动切 GitHub 镜像）。

## P5 · 情报富化：一条 CVE 变成一页档案

- **标题**：10+ 维度自动富化 · 置信度合并 · 宁可缺不可错
- **内容要点**：
  - 维度清单：CVSS/EPSS/KEV/SSVC、PoC+可信度分级、资产测绘、论文关联、CWE→CAPEC→ATT&CK/ATLAS、版本解析、修复建议、中文摘要、相似情报、攻击链、AI 分类；
  - 准确率机制：确定性官方源锁死 → LLM 只做抽取且 evidence+schema 校验 → 校验器闸门 → 低置信 abstain 入复核队列；来源权重 官方1.0>厂商0.95>聚合0.75>LLM0.6；
  - 实测案例卡（CVE-2024-37032）：EPSS 0.897(99.8%) / PoC×9 / 资产≈5312 / 论文×5 / 攻击链 3 段 / 8 worker 全 ok。
- **视觉**：左=情报卡详情页长截图（标注引线）；右=8 worker 状态表 + 合并权重条。
- **讲稿**：45 秒。"富化准确率 5 分看这里：官方字段直接锁死，LLM 产出必须带证据过校验器，置信度不够宁可标存疑——这是'准确率≥95%'设计上的保证，不是口号。"

## P7 · 智能体架构：按任务选模式，不为用而用

- **标题**：LangGraph 三层混合编排 ——【对应 Agent 15 分】
- **内容要点**：
  - 周期链路=确定性 DAG：节点幂等可重放，部分失败可续跑；
  - 交互链路=Supervisor-as-Tools：检索/KG/测绘/报告封装为工具，智能体自主决策调用序；
  - 分析链路=Planner-Executor-Critic：日报含自我校验回环；
  - 共享态：TaskRun 持久化 + Redis 实时节点态；HITL 复核队列（review_status + REST 确认/回炉）；
  - 生产细节：handoff 弹跳预算、worker 只回结论防上下文膨胀。
- **视觉**：三泳道状态图（每条链路一张小型 StateGraph 拓扑），节点用真实节点名；右上贴一张真实 trace 截图。
- **讲稿**：45 秒，本页放慢。"评委如果只看一页，请看这页：三套模式对应三类任务，共享同一份 TaskRun 运行记录与 Redis 实时状态——这是'架构精良且可扩展'的具体含义：加一条新链路=加一张子图，不动存量。"

## 附录 · 备选问答预案（不做进 PPT，备答辩提问）

| 可能的提问 | 应答要点 |
|---|---|
| "和直接查 NVD 有什么区别？" | 三句话：多源去重合并、10+ 维富化（NVD 没有的 EPSS/PoC/资产/攻击链）、自然语言多跳问答 |
| "LLM 幻觉怎么控制？" | 官方字段锁死+evidence+schema 校验+校验器闸门+低置信 abstain+行内引用可回查 |
| "多跳 85% 怎么测的？" | KG 路径自动造桥接题（仿 HotpotQA）+8 题人工基准，`scripts/eval_qa.py` 可现场重跑 |
| "数据规模只有 634？" | 系统刚上线 N 天的自然累积；架构与规模无关，入库管线已验证单轮 NVD 576 条吞吐 |
| "Hunter 模拟数据算造假吗？" | 页面显式 is_simulated 标注=诚实降级设计；管线真实可查，权限开通即真实数据；这正体现 abstain 原则 |
| "为什么用 LangGraph 不用 AutoGen？" | AutoGen 已并入 MS Agent Framework；LangGraph 显式状态图+astream 节点事件最契合三类编排模式（HITL 由独立复核队列承担，可审计可追溯） |
| "断网能不能跑？" | 已入库数据全功能可用；采集层天然异步，恢复后游标续采不丢不重 |
| "创新里哪个最难？" | 四层去重的实体对齐与富化的置信度合并——前者决定'同一漏洞不被拆成五条'，后者决定'准确率敢承诺 95%' |

**制作 checklist**：□ 官方模板套版 □ 全文无学校/人名/队名（含截图与 PDF 元数据）□ 每页一个核心信息，字号 ≥20pt □ 所有数字与 `reports/eval_qa.json`、`docs/04` 一致 □ P9 视频可离线播放（备截图方案）□ 导出 PDF 并逐页翻查渲染。
